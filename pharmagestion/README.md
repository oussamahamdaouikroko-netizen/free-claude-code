# PharmaGestion DZ — مساعد تسيير الصيدلية

> **الحالة: المرحلة 1 مكتملة** — أساس التطبيق، قاعدة البيانات، النسخ الاحتياطي،
> الواجهة بالعربية والفرنسية، ومُثبِّت Windows.
> أقسام المخزون والديون والاستيراد قادمة في المراحل التالية (انظر «خطة المراحل»).

تطبيق سطح مكتب لـ Windows يساعد الصيدلي الجزائري على تسيير:

- المخزون والأدوية والدفعات (اللوت) وتواريخ انتهاء الصلاحية.
- المشتريات والمبيعات وإخراج المخزون.
- ديون العملاء وديون الموردين.
- التنبيهات قبل انتهاء الصلاحية.
- استيراد البيانات من ملفات برامج الصيدلية الأخرى، وتصدير التقارير.

**التطبيق يعمل دون إنترنت**، وكل البيانات تبقى على حاسوب الصيدلية.

التطبيق **لا يعوّض** برنامج الصيدلية الحالي ولا برنامج CHIFA، بل يساعده ويكمله.

## 1. التنصيب (Installation)

**من أين أحمّل الملف؟** من صفحة **Releases** في المستودع على GitHub:

```
https://github.com/oussamahamdaouikroko-netizen/free-claude-code/releases
→ PharmaGestion-DZ-Setup.exe   (الحجم حوالي 100 ميغابايت)
```

بصمة الملف المنشور (SHA-256):
`0816b9c0297bf7e601a1ef56d4f2857e310d5b6262da081e564fdfb993d61f4c`

1. حمّل الملف `PharmaGestion-DZ-Setup.exe`.
2. شغّله بالنقر المزدوج.
3. اختر مجلد التنصيب (أو اترك المجلد الافتراضي).
4. اتبع الخطوات، ثم اضغط **إنهاء**.

بعد التنصيب ستجد:

- أيقونة على **سطح المكتب**.
- أيقونة في **قائمة ابدأ**.
- برنامج إزالة (Uninstaller) في «إعدادات ← التطبيقات».

> لا تحتاج إلى تنصيب Node.js أو أي أداة تطوير.
> لا يحتاج التطبيق إلى صلاحيات مدير النظام، ويُثبَّت للمستخدم الحالي.

المواصفات: **Windows 10 / 11 — 64 بت**.

## 2. أول تشغيل

1. شغّل التطبيق من سطح المكتب.
2. ستفتح **لوحة المتابعة**.
3. اضغط **الإعدادات والنسخ الاحتياطي** وأدخل:
   - اسم الصيدلية، اسم الصيدلي، الهاتف، العنوان (تظهر في التقارير).
   - اللغة: **العربية (RTL)** أو **الفرنسية (LTR)**.
   - حدود التنبيه قبل انتهاء الصلاحية: 90 ثم 60 ثم 30 يوماً (قابلة للتعديل،
     ويجب أن تكون تنازلية).
4. اضغط **حفظ**.
5. اضغط **نسخ احتياطي الآن** لأخذ أول نسخة.

## 3. أين تُحفظ البيانات؟

```
%APPDATA%\PharmaGestion DZ\data\
├── pharmagestion.sqlite          قاعدة البيانات (المخزون، الديون، كل السجل)
├── pharmagestion.log             سجل تقني للمساعدة (دون بيانات العملاء)
├── backups\                      النسخ الاحتياطية
│   ├── pharmagestion-auto-….sqlite
│   ├── pharmagestion-manual-….sqlite
│   ├── pre-update-….sqlite       نسخة تلقائية قبل أي تحديث
│   └── before-restore-….sqlite   نسخة أمان تلقائية قبل أي استعادة
└── exports\                      الملفات المصدّرة
```

**البيانات ليست داخل مجلد التنصيب.** لهذا السبب:

- تحديث التطبيق أو إعادة تنصيبه **لا يحذف** المخزون ولا الديون ولا السجل.
- إزالة التطبيق **لا تحذف** البيانات (هذا مقصود، ولا يتم إلا بموافقة صريحة).

## 4. النسخ الاحتياطي والاستعادة

- **نسخة تلقائية يومية**: تُنشأ مرة واحدة كل يوم عند تشغيل التطبيق.
  (يمكن تعطيلها من الإعدادات.)
- **نسخة يدوية**: زر «نسخ احتياطي الآن» في لوحة المتابعة أو الإعدادات.
- **عدد النسخ المحفوظة**: 30 نسخة افتراضياً (قابل للتعديل).
- **نسخة على قرص خارجي أو مفتاح USB**:
  الإعدادات ← «حفظ نسخة في مكان آخر» ثم اختر المفتاح.

### الاستعادة

الإعدادات ← «استعادة نسخة احتياطية» ← اختر ملفاً.

قبل الاستعادة يقوم التطبيق تلقائياً بـ:

1. فحص سلامة ملف النسخة.
2. إنشاء نسخة أمان من قاعدة البيانات الحالية (`before-restore-…`).
3. استبدال البيانات ثم إعادة تحميل الشاشة.

> **نصيحة مهمة**: خذ نسخة احتياطية قبل أي تحديث كبير، واحفظها على مفتاح USB
> مرة في الأسبوع على الأقل.

## 5. التحديث

1. خذ نسخة احتياطية يدوية.
2. حمّل ملف التنصيب الجديد `PharmaGestion-DZ-Setup.exe`.
3. شغّله فوق النسخة القديمة.
4. عند أول تشغيل بعد التحديث:
   - يأخذ التطبيق نسخة أمان تلقائية (`pre-update-…`) **قبل** أي تعديل على القاعدة؛
   - ثم يحدّث بنية قاعدة البيانات (Migration) داخل معاملة واحدة؛
   - إذا فشل التحديث، تبقى البيانات كما هي ويظهر خطأ واضح.

البيانات في `%APPDATA%` لا تُمس أثناء التحديث.

## 6. الأمان والخصوصية

- `contextIsolation` مفعّل، و`nodeIntegration` معطّل، والنافذة معزولة (sandbox).
- الواجهة تتصل بالعملية الرئيسية عبر **قائمة إجراءات محدودة** فقط
  (`src/main/handlers.js`)، ولا تستطيع الوصول إلى الملفات أو الشبكة مباشرة.
- سياسة أمان المحتوى (CSP) صارمة: `default-src 'none'`، ولا اتصال بالشبكة
  (`connect-src 'none'`)، ولا `eval`.
- لا توجد أي خدمة سحابية، ولا إرسال بيانات، ولا مفاتيح API داخل التطبيق.
- السجل التقني لا يحتوي أسماء العملاء ولا هواتفهم ولا مبالغ الديون.
- المبالغ المالية محفوظة كأعداد صحيحة (سنتيم) لتجنّب أخطاء الحساب.

## 7. للمطوّر: تشغيل المشروع وتوليد المُثبِّت

```bash
cd pharmagestion
npm install          # تثبيت الحزم
npm start            # تشغيل التطبيق أثناء التطوير
npm test             # تشغيل كل الاختبارات (113 اختباراً)
npm run dist         # توليد المُثبِّت: release/PharmaGestion-DZ-Setup.exe
```

بعد `npm run dist` يمكن التحقق من المُثبِّت والحزمة:

```bash
node scripts/verify-package.js --smoke-data "%TEMP%\pg-smoke"
```

> **ملاحظة**: بناء مُثبِّت Windows يتطلب تشغيل الأمر على **Windows**
> (أو على GitHub Actions بنظام `windows-latest`). لا يمكن توليد `.exe` على Linux
> لأن electron-builder يحتاج أدوات NSIS الخاصة بـ Windows.
> سير العمل الجاهز: `.github/workflows/pharmagestion-windows.yml`.

## 9. حدود النسخة الحالية (بصراحة)

- **لا يوجد ادعاء بالتوافق مع CHIFA أو أي برنامج آخر.** الاستيراد/التصدير
  سيُبنى على ملف تصدير حقيقي، ولا يُعلَن التوافق قبل الاختبار عليه.
- أقسام المخزون والديون والتقارير تظهر حالياً كشاشات توضيحية تقول ما ستفعله،
  ولا تعرض جداول فارغة ولا أزراراً لا تعمل.
- لا يوجد تنبيه WhatsApp في هذه المرحلة (وسيأتي لاحقاً دون تخزين أي مفاتيح
  داخل التطبيق).
- الأيقونات مرسومة داخلياً (SVG)؛ لا خطوط أيقونات خارجية ولا اتصال بالشبكة.

## Résumé en français

PharmaGestion DZ est une application Windows **hors ligne** pour les pharmacies
algériennes (stock, lots, péremptions, dettes clients et fournisseurs, imports,
rapports). Interface **arabe (RTL)** et **française (LTR)**.

- Installer : `PharmaGestion-DZ-Setup.exe` (Windows 10/11, 64 bits, sans droits
  administrateur).
- Données : `%APPDATA%\PharmaGestion DZ\data` — jamais dans le dossier
  d'installation ; une mise à jour ou une désinstallation ne les supprime pas.
- Sauvegardes : une par jour + manuelles, restauration avec copie de sécurité.
- Développement : `npm install`, `npm start`, `npm test`, `npm run dist`
  (le dernier doit être lancé sous Windows).
- **Phase 1 livrée** : socle, base SQLite avec migrations, sauvegardes,
  interface bilingue, réglages, installeur NSIS. Les modules stock/dettes/
  imports suivent dans les phases 2 à 5. Aucune compatibilité CHIFA n'est
  annoncée avant essai sur un vrai fichier exporté.
